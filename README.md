# SQL MASTERY LAB

**基礎から実務のDB移行まで学べるSQL実践ラボ**

ブラウザの中で動く本物のPostgreSQL（PGlite）に、実際にSQLを書いて実行しながら学べる無料の学習サイトです。
SELECT の基礎から、DB移行プロジェクトで必要な「調査 → 設計 → マッピング → 移行SQL → 検証 → 障害対応 → 計画・成果物」までを扱います。

**▶ 今すぐ学ぶ：https://gangidenset.github.io/sql-mastery-lab/**

- 登録・ログイン不要、無料です。
- SQLはあなたのブラウザの中だけで実行されます。入力したSQLや学習の記録がサーバーに送られることはありません。
- 練習用のデータ（顧客・注文など）はすべて架空のものです。
- PCでの利用をおすすめします（スマートフォンでも主な機能は使えます）。

## 1. 使い方

### A. Webサイトで使う（おすすめ）

上のURLを開くだけです。初回はSQLエンジン本体（数MB）を読み込むため、少し時間がかかります。

### B. 自分のPCで動かす

`index.html` をダブルクリックして直接開くと動きません（ES Modules と Web Worker のため）。ローカルサーバー経由で開いてください。

| OS | ファイル | 動き |
|---|---|---|
| Windows | `start.bat` | Node.js または Python を自動で探してサーバーを起動し、ブラウザで開きます |
| Mac | `start.command` | 同上（初回は右クリック→「開く」で許可が必要な場合があります） |
| Linux / Mac（ターミナル） | `./start.sh` | 同上 |

- Node.js（推奨）か Python のどちらか一方がインストールされている必要があります。
- 既定のポートは 8080 です。使用中の場合は `start.bat 8081` や `./start.sh 8081` のように番号を指定してください。
- 終了するときは、起動した黒い画面（ターミナル）で Ctrl+C を押すか、画面を閉じます。

手動で起動する場合は、フォルダ内で `python3 -m http.server 8080` または `node tools/server.mjs` を実行し、http://localhost:8080/ を開きます。

### オフラインで使う（任意）

一度だけインターネットにつながる環境で次を実行すると、PGlite が `vendor/pglite/` に保存され、以後はCDNを使わずに起動します。

```bash
node tools/vendor-pglite.mjs
```

### 自分のサイトとして公開する

ビルド不要の静的ファイルだけなので、フォルダをそのまま GitHub Pages・Netlify・Cloudflare Pages などに置けます。
GitHub Pages の場合は、リポジトリの Settings → Pages → 「Deploy from a branch」で `main` ブランチの `/ (root)` を選びます。

## 2. 学習を開始する

1. 起動するとダッシュボードが開きます。「学習をはじめる」で第1章へ。
2. 各レッスンは17項目（学習目標 → 実務での利用場面 → … → 理解度確認テスト → 合格条件 → 次のレッスン）で構成されています。
3. 例の「▶ 実行して結果を見る」で、実際の実行結果を確認できます。
4. 練習問題は SQL を書いて **▶ 実行**（Ctrl+Enter）、**✓ 判定**（Ctrl+Shift+Enter）。ヒントと模範解答は必要なときだけ開きます。
5. 演習すべてに正解し、理解度テストで8割以上正解するとレッスン完了です。
6. LEVEL 3 以降は「DB移行ラボ」（シナリオA〜J）と「総合演習」、最後に「総合試験」に挑戦します。

### 練習DBの初期化

- 各問題の「**DBを初期化**」で、その問題の初期状態に戻せます（DROP や DELETE を試しても大丈夫です）。
- ページを再読み込みすると、練習DBは初期状態に戻ります（進捗は消えません）。
- 構造ビューアでデータセット（基本データ／移行演習データ／大量データ）を切り替えて初期化できます。

### 採点の仕組み（`js/grader.js`）

1. 問題の初期状態で **模範解答** を実行し、結果と全テーブルの状態を記録
2. 同じ初期状態で **学習者のSQL** を実行
3. 比較：実行成功 → 最後の結果（列数・値・行数・必要なら並び順） → 課題ごとのチェックSQL → **全テーブルの件数と内容ハッシュ（意図しない変更がないか）** → 課題の条件（例: NOT EXISTS を使う）→ 危険な書き方（WHEREなしの更新など）

書き方が模範解答と違っても、結果と安全性が同じなら正解になります。

### 安全性

- 練習DBはブラウザ内のPGliteのみ。接続先を変える機能はありません。
- SQLは Web Worker で実行し、**10秒**を超えるとWorkerごと停止 → エンジンを作り直して練習DBを復元します（無限ループや巨大な生成もアプリを止めません）。
- DBサイズが300MBを超えたら自動で初期化。表示は最大500行。大量データ演習は最大20万件に制限。
- WHEREのない UPDATE/DELETE、DROP、TRUNCATE などは実行前に確認画面を出します（文字列チェックは「気づき」のためで、安全対策の本体は上の環境分離と制限です）。

## 5. 技術構成

- 素の HTML / CSS / JavaScript（ES Modules）。フレームワーク・ビルド不要
- SQLエンジン：**PGlite**（`@electric-sql/pglite` 0.5系、なければ0.4系）＝ WebAssembly版 PostgreSQL 17系。Web Worker で実行
- 保存：ブラウザの localStorage（キー `sml.progress.v1`）
- フォント：IBM Plex Sans JP / IBM Plex Mono（Google Fonts。読み込めない環境では端末のフォント）

### SQLエンジンの制約

- 接続（セッション）は1つ。複数接続による同時更新・ロック待ち・分離レベルの違いは体験できません（説明のみ）。
- BEGIN / COMMIT / ROLLBACK / SAVEPOINT、EXPLAIN / EXPLAIN ANALYZE、CTE、ウィンドウ関数、ON CONFLICT、PL/pgSQL の DO ブロック、`pg_input_is_valid` は動作します。
- ユーザー・権限（GRANT / REVOKE）、COPY でのファイル読み書き、拡張機能の追加、レプリケーション、DBLINK は対象外です。
- 実行時間はブラウザ内の小さなDBでの値です。本番性能の目安ではなく、改善前後の比較に使ってください。

## 9. 未実装・制約

- 記述式（設計理由・手順書など）の採点は、文字数とキーワードによる「目安」です。内容の正しさは自己点検チェックリストで確認します。
- 複数接続のロック・分離レベルは体験できません（エンジンの制約）。
- 練習DBの状態はページを再読み込みすると初期化されます（進捗は保持）。
- 実在のDB（Oracle / SQL Server / MySQL 等）への接続機能はありません（要件どおり初期バージョンでは未実装）。
- 方言の違い（Oracle の MERGE や ROWNUM など）は説明のみで、実行できるのは PostgreSQL の構文です。
